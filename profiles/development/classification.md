# 开发分级与蓝图

[← Development](README.md)

开发定档同时考虑结构尺度、接口影响和交付跨度。

| 档位 | 判据 | 流程 |
|---|---|---|
| 蓝图级 | 跨多个子系统、新增或重设计公共接口、需要多期交付 | 开发蓝图 → 蓝图复核 → Gate 1 → 各期走标准级 |
| 标准级 | 单项目内多个模块，接口和交付物明确，无跨系统重设计 | 完整方案、双复核、双 Gate |
| 轻量级 | 少量相邻文件、无新公共接口、无数据结构变化，看 diff 可验收 | 需求简记 → 实施 → 测试/diff 证据 → 用户 Gate |

定档与升档遵守 [Core 分级规则](../../core/classification.md)。约 200 行、3–8 个模块等数字只能作为经验锚点，不能作为绕开流程的硬边界。

## 蓝图内容

蓝图只定义整体目标、非目标、模块边界、公共契约、分期、依赖、终态验收和回滚策略，不提前展开后期实现细节。

- 第一期应当是能证伪关键假设的垂直切片；
- 每期独立走标准级流程，上一期未验收不开始下一期实施；
- 后续期方案在前期结束后再细化；
- 试点证明蓝图不成立时，出蓝图新版本并重新复核。
