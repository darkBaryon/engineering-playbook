# 实施、预飞与并行开发

[← Development](README.md)

## 标准执行

1. 需求查重、定档；
2. 方案通过独立复核；
3. Gate 1 由用户放行；
4. 在功能分支按步骤小步实施，每步相关检查通过后提交；
5. 追加实施记录、偏差记录和蓝图验证备忘（不适用时明确写出）；
6. 运行 checklist 生成预飞事实表；
7. 代码独立复核，修订走差量确认轮；
8. Gate 2 用户验收后，按项目规则集成和归档。

## 终扫

- 临时日志、断点、注释掉的旧代码和临时 TODO 清零；
- 本期新增但未使用的函数、参数、分支和配置删除；
- 实际公共接口与方案声明对账；
- 自动化测试、构建或 demo 自跑；
- 生成物按项目工具重建并确认零漂移。

## 并行开发

并行是纵向开发流程之外的横向约束：

1. 一条功能线对应一条分支、一个 Worktree 和一个实施会话；
2. 修改 Git 前先确认当前目录和分支；
3. 集成分支是唯一汇合点，后合者先吸收最新集成分支并解决冲突；
4. 多条线共用的契约改动优先独立落地；
5. 改动足迹高度相交时排队，不伪装并行；
6. 生成文件冲突通过生成器重建，不手工拼接。

具体分支名、合并方式和集成规则由项目适配声明。
