# 重构评审与终扫

[← Refactoring](README.md)

## 评审重点

除 [Core 独立复核](../../core/review.md)外，重构评审必须验证：

- 基线事实和调用方盘点是否完整；
- 每个迁移 commit 是否只执行声明的步骤；
- 行为测试断言的是业务语义，而不是碰巧的源码形态；
- 公共签名 diff 是否落在白名单；
- 旧接缝、临时兼容层和已废弃代码是否按计划清理；
- 实际偏差是否与偏差记录一致。

## “碰巧同形”

重复扫描发现相似代码，不代表必须抽象。业务本质不同但结构相似的代码可以进入带证据的留存白名单；判断依据必须可证伪，最终合并或留存由用户裁决。没有证据的“以后可能复用”不构成保留理由。

## 阶段终扫

项目支持时，阶段结束至少执行：

1. 格式、静态检查、全量测试和构建；
2. 重复代码扫描，与基线逐组对账新增、消除、位移和白名单；
3. 死代码扫描，与基线对账，零新增不可达；
4. 公共接口签名 diff 与白名单逐项核对；
5. 生成代码重建并确认零漂移；
6. 长期架构文档回填。

工具或语言不支持某项扫描时，方案必须给出替代核验或明确盲区，不能静默省略。
