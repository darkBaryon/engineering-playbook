# 重构流程与实施记录

[← Refactoring](README.md)

## 标准流程

1. 结构问题查重、立案并定档；
2. 设计职责建立蓝图或方案，固定基线、行为口径、调用方和白名单；
3. 复核职责全量评审方案；需修改则出新版本；
4. Gate 1 由用户确认重构方向和迁移范围；
5. 实施职责在隔离分支按步骤迁移，每步保持可编译、可测试；
6. 实施完成后追加实施记录、偏差记录和蓝图验证备忘；
7. 运行 checklist 和阶段终扫，事实表全绿才交代码评审；
8. 复核职责按基线、方案和 commit 对账；修订走差量确认轮；
9. Gate 2 用户验收行为与终态后，按项目规则集成、回填和归档。

步骤较多时允许分批“实施 → 预飞 → 代码评审”，但上一批阻塞未关闭前不得开始下一批实施。

## 实施记录

- **实施记录**：步骤、commit、一句话说明和验收自查；
- **实施偏差记录**：与方案不符或漏做的内容；无则明确写“无”；
- **蓝图验证备忘**：试点期记录接口表达力、关键假设和是否需要修订蓝图。

任何偏差按 [Core 变更协议](../../core/deviations.md)处理。
