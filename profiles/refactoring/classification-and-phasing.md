# 重构分级与分期

[← Refactoring](README.md)

重构定档主要看结构尺度。

| 档位 | 判据 | 流程 |
|---|---|---|
| 蓝图级 | 跨多个包或子系统、设计模式级变化、重设计被广泛依赖的公共 API | 蓝图、分期、可证伪试点、各期完整循环、双 Gate |
| 标准级 | 主体在一个模块内，少量外部调用方需要迁移 | 瘦方案、方案复核、迁移、聚焦代码复核、双 Gate |
| 轻量级 | 模块内少量文件、无关键契约变化、diff 可完整核对 | 台账简记、机械证据、用户 Gate |

遵守 [Core 分级保险丝](../../core/classification.md)。标准期应控制在一次评审能够完整理解的尺寸；commit 过多既可能说明需要拆期，也可能说明步骤切得过碎。

## 蓝图级分期

- 蓝图定义终态、接口契约、分期和最终验收，不提前写完所有期的细节；
- 第一期必须是可证伪的垂直切片，交付的是“被验证的蓝图”；
- 每期按标准级走完整方案、实施、复核和 Gate；
- 后续期在前期稳定后再计划；
- 关键假设被证伪时停止本期，修订蓝图并重新 Gate 1。
