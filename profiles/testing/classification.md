# 测试风险分级与准入

[← Testing](README.md)

测试分级只看失败后果、影响面和验证难度，不按代码行数判断。

| 档位 | 判据 | 最低测试组合 |
|---|---|---|
| 轻量级 | 纯文案/样式、纯函数小修，失败易发现、易回滚且不改变业务数据 | 相关静态检查 + 单元/组件测试或精确人工检查 + diff 复核 |
| 标准级 | 页面/API 交互、状态流转、普通数据解析或兼容性变化 | 轻量级全部 + 可运行产物 + 主路径 + 相关回归 + 独立测试记录 |
| 高风险级 | 支付、合同、身份、权限、关键数据写入、不可逆操作、跨系统或第三方链路 | 标准级全部 + 有效测试数据端到端 + 失败/取消/重试 + 结果状态核对 + 业务验收 |

## 保险丝

- 执行中发现失败后果或验证难度更高，立即升档补齐测试计划；
- 测试对象发生变化，受影响结论失效；无法机械证明无关时重新执行相关用例和回归；
- 缺账号、数据、服务或平台条件时记为“阻塞”，不能用低层测试代替高层结论。

## Gate T0：测试准入

进入执行中之前必须确认：

- 测试对象已提交并可获取，不在持续变化；
- 完整 commit、构建标识或产物哈希与测试计划一致；
- 业务工作区和构建输入可解释，无未声明改动；
- 必要静态检查、自动化测试和构建完成；
- 运行时环境、设备或平台与计划一致；
- 测试账号、数据和外部依赖已准备，或阻塞范围已明确；
- 用例包含前置条件、单步操作、期望、回归范围和证据要求。

Gate T0 只证明“可以正确开始测试”，不证明功能正确。
