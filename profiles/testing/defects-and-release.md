# 缺陷、复测与发布准入

[← Testing](README.md)

## 缺陷回流

失败记录至少包含：来源、失败用例、精确测试对象、环境与平台、最短复现、期望与实际、原始证据、严重级别和影响范围。

修复职责完成修改后：

1. 尽可能增加能稳定复现问题的自动化测试；无法自动化时说明原因；
2. 提供新的精确 commit 或产物；
3. 新建下一轮测试记录，不覆盖旧轮；
4. 先复测上轮失败项，再覆盖修复影响范围和相关回归；
5. 无法证明其他范围不受影响时恢复全量测试。

## Gate T1：测试通过

测试职责确认全部必测项通过、阻塞清零、证据完整、没有未覆盖的新版本变化，才能给出“已通过”。开发者自己的测试只能作为开发自测，不能替代独立 Gate T1。

## Gate T2：业务验收

用户阅读 Gate 卡片，决定业务结果和剩余风险是否可接受。未获得明确确认时，状态保持“待业务验收”。

## 发布准入

至少满足：

- Gate T1 和 Gate T2 均通过；
- 最高优先级缺陷清零，其他遗留风险已被明确接受；
- 测试记录绑定当前候选版本，没有未覆盖的新变化；
- 高风险功能完成有效数据的端到端与结果核对；
- 项目自己的合并、发布和审批规则已满足。

“已推送供测试”“测试包可安装”或“已创建合并请求”都不等于获准发布。集成后应执行项目规定的最小冒烟，失败则停止发布并回到缺陷流程。
