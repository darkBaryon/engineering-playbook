# 测试执行与证据

[← Testing](README.md)

## 分层执行

1. **差异核对**：确认测试对象与计划一致，阅读相对基线的变更和影响面；
2. **机械检查**：格式、静态分析、单元和组件测试；存量基线错误单列；
3. **构建或部署**：记录命令、模式、产物和哈希；
4. **运行态确认**：核对实际环境、版本、设备或平台；
5. **主路径**：按业务顺序逐步执行；
6. **反例与边界**：取消、返回、重复触发、空数据、失败响应、权限拒绝等；
7. **回归**：覆盖公共组件、调用方和相邻业务；
8. **结果核对**：高风险操作检查真实数据或后续状态，不以提示消息替代结果。

根据项目选择模拟器、真机、浏览器、API、数据库或第三方端。使用共享设备时，锁、容量、单步操作和故障处置由项目规则定义。

## 用例要件

每个用例包含：编号、优先级、前置条件、单步操作、每步期望、实际结果、证据和结论。

结论枚举：

- `通过`：全部步骤符合期望且证据充分；
- `未通过`：可以执行，但实际与期望不符；
- `阻塞`：外部条件导致无法执行；
- `不适用`：经计划明确裁决不属于本轮；
- `未执行`：尚未执行，不计入通过率。

## 最小证据

- 版本：分支、完整 commit、基线和 diff 摘要；
- 产物：构建方式、文件或部署标识、内容哈希；
- 环境：运行态环境证据；
- 平台：设备、系统、浏览器或运行时版本及关键模式；
- 自动化：命令、退出码和统计；
- 行为：关键步骤证据，失败时附稳定复现和日志；
- 数据：脱敏的可追踪标识；
- 结论：覆盖统计、遗留风险、测试者和时间。
