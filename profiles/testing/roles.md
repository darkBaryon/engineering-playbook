# 测试职责与交测包

[← Testing](README.md)

| 职责 | 主要责任 | 不得做的事 |
|---|---|---|
| 开发职责 | 写测试计划初稿、补自动化测试、完成开发自测、提供精确版本和已知盲区 | 把自己的自测写成独立测试通过 |
| 测试职责 | 独立核对版本和环境、执行用例、补充反例、记录原始证据并给出结论 | 修改被测代码、采信口头结论、把未执行或阻塞判成通过 |
| 修复职责 | 根据失败证据修复、补回归测试、提供新版本 | 覆盖旧测试记录、混入无关改动 |
| 决策职责 | 确认风险档位、提供或授权测试条件、接受剩余风险、业务验收 | 重复测试职责已经完成的机械检查 |

同一会话实现并执行的测试标记为“开发自测”。独立测试必须重新核对测试对象、运行条件并亲自执行规定范围。

## 最小交测包

- 需求或缺陷来源与一句话目标；
- 基线、分支、完整 commit 或版本；
- 构建/部署方式、产物标识和哈希；
- 风险档位、必测用例、回归范围和非目标；
- 开发自测事实表、已知风险、账号/数据/外部依赖准备说明。
