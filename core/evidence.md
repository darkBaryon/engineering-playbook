# 证据与历史

[← Core](README.md)

## 基线

- Git 项目使用完整 commit SHA；所有 diff、复核和验收以它为参照。
- 构建或发布产物记录文件名、构建方式和内容哈希。
- 非 Git 工作记录起点文件清单、版本或时间戳。
- 环境和设备会影响结果时，记录其实际运行态，而不是只记录配置文件中的期望值。

## 事实表

可机械验证的内容进入 checklist，由固定脚本执行并生成事实表。典型项目包括：格式、静态检查、测试、构建、必要文件、必含符号、禁留标记和生成物零漂移。

脚本只能证明“命令得到什么结果”，不能证明目标、接口或业务行为设计正确；后者归独立复核。

## 历史不可覆盖

- 方案被判“需修改”时产生新版本，旧版冻结；
- 评审和测试按轮次递增，新轮次引用上轮阻塞项；
- Gate 决策确需落回已批准文档时，必须新增决策章节并标注来源；
- 历史记录按当时采用的 Playbook 版本解释，不追溯改写。

## 敏感信息

证据不得包含 token、密码、完整身份信息、合同全文或生产客户数据。使用脱敏标识，必要原始证据放入受控存储，只在记录中留下引用。
