# 状态机与 Gate

[← Core](README.md)

状态表示已经完成的事实，Gate 表示需要显式决策的边界。两者不能靠聊天语气或默认推断推进。

## 通用骨架

```text
立案 → 准备/方案 → 独立复核 → Gate 1
     → 执行 → 预飞自检 → 独立复核 → Gate 2
     → 集成/交付 → 归档
```

Profile 可以增加 Gate，例如测试准入 Gate，但必须定义：谁决定、依据什么、通过后进入什么状态。

## Gate 卡片

每次请求 Gate 必须提供：

- **结论一句话**：本次放行的对象和版本；
- **覆盖情况**：已完成、失败、阻塞和未执行项；
- **拍板项**：只有用户能决定的业务取舍、风险或成本；无则写“无”；
- **抽查菜单**：1–3 个现成命令、证据或操作路径；
- **最大剩余风险**：最值得知道的一条；
- **下一动作**：通过和不通过分别会发生什么。

## 用户职责边界

用户负责定档、业务取舍和最终接受，不重复承担静态检查、逐文件核对等技术体力活。技术事实由机械检查和复核职责先建立证据。
