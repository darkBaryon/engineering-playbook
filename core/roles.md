# 职责与独立性

[← Core](README.md)

流程骨架按职责书写。角色分配可以随团队和工具变化，但职责边界不跟着变化。

## 通用职责

| 职责 | 责任 |
|---|---|
| 设计职责 | 查重、定档提议、定义目标与非目标、写方案、维护状态、整理 Gate 卡片 |
| 实施职责 | 按已批准范围小步执行、自检、记录实施事实和偏差，不擅自改变目标 |
| 复核职责 | 独立验证方案、代码或测试结论，记录证据，只给结论和意见 |
| 决策职责 | 由用户承担定档、业务取舍、风险接受、Gate 放行和冲突裁决 |

Profile 可以增加专项职责，例如测试流程的测试职责和修复职责，但必须映射回以上边界。

## 独立性

- 设计和实施可以由同一人或同一 Agent 承担。
- 正式复核不得与被复核工作共享同一判断上下文；至少需要独立会话重新读取基线、产物和证据。
- 实施者的自检只能证明“可以交给复核”，不能替代独立结论。
- 复核职责不直接修改被复核产物；发现问题后切回设计、实施或修复职责处理。
- 无独立验证记录的正式复核无效。

## 交接

一次有效交接至少包含：任务来源、范围、基线、当前版本、产物、已执行检查、偏差、阻塞和下一 Gate。对话历史可以辅助理解，但不是唯一事实源。
